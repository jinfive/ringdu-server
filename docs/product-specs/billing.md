# 학생 청구서와 수납

## 1. 목적

학원 운영자가 학생 관리 화면에서 학생별 월 수강료를 청구하고 수납 상태를 관리한다. 실제 결제 수단을 제공하기보다 청구 금액과 납부 현황을 정확히 기록하는 것이 MVP의 범위다.

## 2. 사용자와 위치

- `ACADEMY`만 학생 청구 설정과 청구서를 생성, 수정, 수납, 취소할 수 있다.
- 기능은 `/academy/students`와 학생 상세의 `청구/수납` 탭에 둔다.
- 별도 사이드바 메뉴와 학부모 청구 조회는 이번 범위에 포함하지 않는다.

## 3. 수납 설정

- 학생별 월 수강료, 수납 기준일, 메모를 저장한다.
- 수납 기준일은 매월 1일부터 28일까지만 허용한다.
- 설정은 학원과 학생 조합마다 하나만 존재한다.

## 4. 월 청구서

- 화면 진입 시 프론트가 명시적인 `ensure-current` POST API를 한 번 호출한다.
- 오늘이 수납 기준일 이상이고 현재 월 청구서가 없으면 설정된 수강료로 청구서를 생성한다.
- 아직 기준일 전이면 생성하지 않는다.
- 같은 학원, 학생, 청구월의 청구서는 하나만 존재한다.
- 조회 API에는 데이터 생성 부작용을 두지 않는다.

## 5. 상태와 금액

```txt
paidAmount = 0                  -> UNPAID
0 < paidAmount < amount        -> PARTIAL
paidAmount >= amount           -> PAID
운영자가 취소한 청구서         -> CANCELED
```

- 청구 금액은 수정할 수 있지만 이미 수납한 금액보다 작게 낮출 수 없다.
- 수납 금액은 0보다 커야 하며 남은 미납 금액을 초과할 수 없다.
- 취소된 청구서는 수정하거나 수납할 수 없다.
- 완납된 청구서는 취소할 수 없다.
- 수납 처리는 이력으로 남기고 청구서의 누적 수납 금액을 갱신한다.

## 6. 권한

- 모든 요청에서 로그인한 학원의 ID와 학생 프로필의 학원 ID가 일치해야 한다.
- 청구서의 학원 ID와 학생 프로필 ID가 URL의 학생과 일치해야 한다.
- 다른 학원의 학생, 설정, 청구서에는 접근할 수 없다.

## 7. 제외 범위

- PG, 카드, 계좌 결제
- 자동 배치와 외부 청구서 발송
- 학부모 청구 조회
- 환불과 수납 취소 이력
