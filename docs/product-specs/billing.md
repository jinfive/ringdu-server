# 학생 청구서와 수납

## 1. 목적

학원 운영자가 학생 관리 화면에서 학생별 정규 수강료와 선납, 보강비, 교재비 등 임의 청구를 생성하고 수납 상태를 관리한다. 실제 결제 수단을 제공하기보다 청구 금액과 납부 현황을 정확히 기록하는 것이 MVP의 범위다.

## 2. 사용자와 위치

- `ACADEMY`만 학생 청구 설정과 청구서를 생성, 수정, 수납, 취소할 수 있다.
- `PARENT`는 활성 연결 자녀의 청구와 수납 상태를 조회할 수 있다.
- `STUDENT`는 본인 계정에 연결된 학생 프로필의 청구와 수납 상태를 조회할 수 있다.
- 기능은 `/academy/students`와 학생 상세의 `청구/수납` 탭에 둔다.
- 학생 상세 탭에는 이번 달 요약만 표시하고, 상세 관리는 반응형 모달에서 제공한다.
- 학원 역할에는 별도 청구 사이드바 메뉴를 추가하지 않는다.

## 3. 수납 설정

- 학생별 월 수강료, 수납 기준일, 메모를 저장한다.
- 수납 기준일은 매월 1일부터 31일까지 허용한다.
- 선택한 기준일이 해당 월에 없으면 그 달의 마지막 날을 납부 기준일로 사용한다.
- 설정은 학원과 학생 조합마다 하나만 존재한다.

## 4. 정규 월 청구서

- 화면 진입 시 프론트가 명시적인 `ensure-current` POST API를 한 번 호출한다.
- 오늘이 수납 기준일 이상이고 현재 월 청구서가 없으면 설정된 수강료로 청구서를 생성한다.
- 아직 기준일 전이면 생성하지 않는다.
- 같은 학원, 학생, 청구월의 `REGULAR` 자동 청구서는 하나만 존재한다.
- 조회 API에는 데이터 생성 부작용을 두지 않는다.

## 5. 임의 청구서

- 학원은 `REGULAR`, `PREPAID`, `MAKEUP`, `TEXTBOOK`, `ETC` 유형의 청구를 직접 생성할 수 있다.
- 청구 기간은 `billingPeriodStartMonth`부터 `billingPeriodEndMonth`까지이며 시작월은 종료월보다 늦을 수 없다.
- 3개월 선납도 월별 청구서로 나누지 않고 하나의 청구서로 저장한다.
- 대표 청구월인 `billingMonth`는 청구 기간의 시작월을 사용한다.
- 같은 기간에 보강비나 교재비 등 여러 임의 청구가 존재할 수 있으므로 수동 생성에는 중복 제한을 두지 않는다.

## 6. 상태와 금액

```txt
paidAmount = 0                  -> UNPAID
0 < paidAmount < amount        -> PARTIAL
paidAmount >= amount           -> PAID
운영자가 취소한 청구서         -> CANCELED
```

- 청구 금액은 수정할 수 있지만 이미 수납한 금액보다 작게 낮출 수 없다.
- 수납 금액은 0보다 커야 하며 남은 미납 금액을 초과할 수 없다.
- 취소된 청구서는 수정하거나 수납할 수 없다.
- 완납된 청구서는 취소할 수 없다.
- 수납 처리는 이력으로 남기고 청구서의 누적 수납 금액을 갱신한다.

## 7. 권한

- 모든 요청에서 로그인한 학원의 ID와 학생 프로필의 학원 ID가 일치해야 한다.
- 청구서의 학원 ID와 학생 프로필 ID가 URL의 학생과 일치해야 한다.
- 다른 학원의 학생, 설정, 청구서에는 접근할 수 없다.
- 학부모는 `ACTIVE` 부모-학생 관계가 있는 자녀 프로필만 조회할 수 있다.
- 학생은 자신의 `userId`에 연결된 활성 학생 프로필만 조회할 수 있다.
- 학부모와 학생에게는 청구 수정, 수납, 취소 API를 제공하지 않는다.

## 8. 제외 범위

- PG, 카드, 계좌 결제
- 자동 배치와 외부 청구서 발송
- 환불과 수납 취소 이력
