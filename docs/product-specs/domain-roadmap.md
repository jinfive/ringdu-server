# Domain Roadmap

## 0. 학원 도메인

`Academy`는 `ACADEMY` 역할의 `User`와 1:1로 연결되는 실제 학원 정보다.

현재 구현 범위:

```txt
ADMIN 학원 가입 신청 승인
→ ACADEMY User ACTIVE 전환
→ AcademySignupApplication APPROVED 전환
→ Academy 생성
→ /api/academies/me 조회/수정
→ /api/academies/me/dashboard 0건 기반 요약 제공
```

대시보드 요약은 등록 학생, 등록 선생님, 이번 달 미납, 신규 상담 대기만 제공한다. 운영 클래스, 오늘 출석 현황, 출석 승인 대기는 학원 홈 요약에 포함하지 않는다.

## 1. 학원-선생님 연결

학원-선생님 연결은 초대코드 직접 입력 방식이 아니라 초대장 기반 수락/거절 플로우로 간다.

```txt
학원이 선생님 이메일/전화번호로 초대장 생성
→ 선생님 계정에 초대장이 표시됨
→ 선생님이 수락 또는 거절
→ 수락하면 AcademyMember 생성
→ 거절하면 초대 상태 REJECTED
```

MVP 구현 범위:

```txt
ACADEMY가 선생님 초대장 생성
ACADEMY가 보낸 초대장 목록 조회
ACADEMY가 소속 선생님 목록 조회
TEACHER가 받은 초대장 목록 조회
TEACHER가 초대장 수락/거절
수락 시 학원-선생님 소속 관계 생성
```

문자/이메일 실제 발송은 이번 범위가 아니다. 초대장은 Ringdu 웹/앱 내부에서 확인한다.

## 2. 학원 학생 관리

학원이 학생 정보를 직접 등록하고 관리한다. 학생이 아직 Ringdu 회원이 아니어도 등록할 수 있다.

단, 이미 Ringdu 계정이 있는 학생의 경우 **자동으로 연결하지 않고 초대장 수락/거절 플로우**를 거친다.

```txt
학원이 학생 정보를 입력해 비회원 StudentProfile 생성 (이름 필수)
→ 학생 이메일/전화번호로 기존 계정 검색
→ 기존 계정이 발견되면 "초대장 보내기" 선택 가능
→ 학생 계정에 학원 초대장이 표시됨
→ 학생이 수락하면 StudentProfile에 userId가 연결됨
→ 거절하면 초대 상태 REJECTED, 비회원 프로필로 유지
```

MVP 구현 범위:

```txt
ACADEMY가 학생 비회원 등록 (이름 필수, 연락처 선택)
ACADEMY가 학생 후보 검색 (Role=STUDENT, 이메일/전화번호 일치)
ACADEMY가 학생 계정에 초대장 발송
ACADEMY가 소속 학생 목록 조회 (연결 상태 표시)
STUDENT가 받은 학원 초대장 조회/수락/거절
학원 연락용 보호자 전화번호(guardianPhone) 1개 저장 가능 (수동 저장 전용)
```

## 3. 부모-학생 연결

부모-학생 연결은 선택 기능이다. 학원 학생 등록 시 부모 연결은 필수가 아니며, 부모는 학원 멤버가 아니다.

부모-학생 연결은 초대코드 직접 입력 방식이 아니라 양방향 초대장 기반 수락/거절 플로우로 간다.

학원 측에서도 부모 계정 후보를 검색할 수 있으나, **학원이 직접 부모를 연결하지 않는다.**

```txt
부모가 학생에게 연결 초대 → 학생이 수락
학생이 부모에게 연결 초대 → 부모가 수락
학원이 부모 계정 후보를 검색해 알려줄 수 있으나, 실제 연결은 부모-학생 당사자 간 초대 시스템을 활용
```

MVP 구현 범위:

```txt
PARENT가 STUDENT에게 연결 초대장 생성
STUDENT가 PARENT에게 연결 초대장 생성
PARENT/STUDENT가 자기 초대장 목록 조회
수락 시 부모-학생 관계(ParentStudentRelation) 생성
학원은 보호자 전화번호(guardianPhone)만 수동 저장하며, 부모 계정은 직접 연결하지 않음
```

같은 `parentUserId + studentUserId` 관계는 중복 생성하지 않는다. ACADEMY는 부모-학생 관계의 직접 당사자가 아니다.

## 4. 상담 관리

상담 관리는 신규 등록 CRM이 아니다. MVP의 상담 관리는 실제 재원생 학생 관리 하위 기능이다.

잘못된 방향:

```txt
상담 고객 등록
상담 후 등록 여부 결정
등록 완료 시 학생으로 전환
```

최신 방향:

```txt
상담 관리는 실제 재원생의 학생/학부모 상담 기록 관리 기능이다.
학원과 선생이 상담 기록을 작성한다.
부모 상담 요청 기능은 후순위로 검토한다.
```

상담 흐름:

```txt
선생 또는 학원이 학생 상담 등록
→ 상담 일정 기록
→ 학생 또는 학부모 상담 진행
→ 상담 내용 작성
→ 학습 상태/태도/진도/출결 관련 메모 작성
→ 후속 조치 또는 다음 상담 일정 관리
```

상담 유형:

```txt
학습 상담
출결 상담
숙제 상담
성적 상담
생활 태도 상담
학부모 상담
진로 상담
기타
```

상담 기록 항목:

```txt
상담 대상 학생
상담 작성자
상담 대상자: 학생 / 부모 / 학생+부모
상담 유형
상담 일시
상담 제목
상담 내용
후속 조치
다음 상담 예정일
공개 여부
```

공개 범위:

```txt
학원 내부용
선생 공유용
부모 공개용
```

내부 메모는 부모에게 보이지 않아야 하고, 부모에게 공개 가능한 상담 내용만 부모 화면에 표시한다.

## 5. 출석 도메인

출석은 학생 요청 + 선생 승인 방식으로 간다.

```txt
학생이 해당 클래스에 들어감
→ 출석 버튼 클릭
→ 출석 요청 생성
→ 선생이 승인 또는 반려
→ 승인 시 출석 처리
```

출석 상태:

```txt
출석 요청
출석 완료
지각
결석
반려
취소
```

MVP에서는 QR, 위치 인증, Wi-Fi 인증은 제외한다. 다음은 후순위 확장 기능이다.

```txt
QR 출석
수업 시간 내 출석 제한
위치 기반 출석
교실 Wi-Fi 인증
자동 결석 처리
출석 알림톡 발송
```

## 6. 청구서/수납

초기에는 실제 결제 연동보다 청구서와 수납 상태 관리부터 구현한다.

```txt
학원이 청구서 생성
→ 부모가 청구서 확인
→ 학원이 수납 상태 변경
→ 부모가 납부 상태 확인
```

청구서 상태:

```txt
청구됨
납부 완료
미납
취소
```

추후 확장:

```txt
카카오 알림톡 청구서 발송
미납 자동 알림
계좌이체 안내
PG 결제 연동
카드 결제 연동
충전형 알림 발송 포인트
```

수익화 방향은 카드 수수료 전가가 아니라 다음 방식으로 정리한다.

```txt
월 무료 알림 제공량
초과 알림톡 충전
미납 자동 알림 유료화
고급 청구서 기능 유료화
추후 구독형 프리미엄 기능
```

## 7. 커뮤니티

Ringdu 커뮤니티는 크게 두 개로 나눈다.

```txt
학생 커뮤니티
학부모 커뮤니티
```

학생 커뮤니티는 학습 중심으로 운영한다.

```txt
숙제 공유
질문 게시판
공부 자료 공유
시험 정보 공유
클래스별 게시판
자유 게시판
```

학부모 커뮤니티는 학원 정보 공유와 교육 정보 공유를 중심으로 한다.

```txt
지역별 학원 정보 공유
학원 후기
교육 정보 공유
자녀 학습 고민
학원 추천
질문 게시판
```

관리 기능:

```txt
게시글 신고
댓글 신고
작성자 차단
선생/학원 삭제 권한
```

## 8. 광고

광고는 학부모 커뮤니티와 연결한다. MVP 이후 단계에서 구현한다.

광고 방식:

```txt
지역별 학원 광고
과목별 학원 광고
커뮤니티 상단 배너
추천 학원 노출
학원 상세 페이지 연결
```

광고 상품 후보:

```txt
무료 학원 프로필
유료 상단 노출
유료 배너 광고
지역/과목 타겟 광고
학원 홍보 게시글
```

알림 종류:

상담 일정 알림

```txt
월 기본 무료 알림 제공
초과 발송은 포인트 충전
카카오 알림톡 연동
문자 대체 발송
```

```txt
학원 관리
선생 관리
학생 관리
클래스 관리

숙제 관리 기본 기능
커뮤니티 기본 이용
```

유료 후보:

카카오 알림톡 초과 발송
