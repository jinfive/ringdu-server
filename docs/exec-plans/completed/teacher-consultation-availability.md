# 실행 계획: 선생님별 상담 가능 시간

## 1. 목표

재원생 상담 가능 시간을 선생님별로 관리하고, 학부모가 담당 선생님과 비어 있는 시간대를 선택해 상담을 요청하도록 변경한다.

## 2. 배경

현재 상담 가능 시간은 학원 단위라 실제 상담 담당자 일정과 예약 점유 상태를 반영하지 못한다.

## 3. 작업 범위

포함:

- 선생님별 상담 가능 시간 저장 및 겹침 검증
- 학원 전체 선생님 관리, 선생님 본인 관리 API
- 담당 학생 기준 학부모 선생님 선택
- 월별 날짜/시간 슬롯과 예약 점유 상태 조회
- 상담 요청 생성 시 담당 선생님, 가능 시간, 중복 예약 검증
- 학원 설정, 선생님 상담 관리, 학부모 예약 UI
- 학원 대표 상담 담당자와 가능 시간
- 정확히 배정된 선생님의 활성 상담 요청 조회 및 완료 처리
- 완료, 취소, 거절 상태의 활성 목록 제외

제외:

- 비회원 및 신규생 공개 상담
- 청구, 수납, 출석
- 외부 캘린더 라이브러리
- 사이드바 구조 변경

## 6. 구현 순서

1. 선생님별 가능 시간 데이터와 저장소 쿼리를 변경한다.
2. 학원/선생님 관리 API와 권한 검증을 구현한다.
3. 학부모 옵션과 월별 예약 가능 슬롯 API를 구현한다.
4. 상담 요청 생성 검증을 선생님과 겹치는 예약 기준으로 강화한다.
5. 역할별 프론트 UI와 API 계약을 연결한다.
6. 자동 테스트와 브라우저 흐름을 검증한다.

## 7. 검증 방법

- `./gradlew test`
- `npm run lint`
- `npm run build`

## 8. 위험 요소

- 기존 학원 공통 가능 시간 데이터에는 선생님 식별자가 없다.
- 같은 선생님이 여러 학원에 연결된 경우 학원별 슬롯을 구분해야 한다.
- 조회 후 생성 사이 동시 요청은 애플리케이션 검증만으로 완전히 직렬화되지 않는다.

## 9. 롤백 방법

기능 브랜치 커밋을 되돌리고 기존 학원 단위 가능 시간 API 계약으로 복원한다.

## 10. 완료 기준

- [x] 학원과 선생님이 허용된 범위의 선생님별 슬롯을 관리한다.
- [x] 학부모가 담당 선생님의 비어 있는 슬롯만 선택한다.
- [x] REQUESTED와 APPROVED 요청이 겹치는 슬롯을 점유한다.
- [x] 상담 요청 생성 시 서버에서 모든 권한과 시간 조건을 재검증한다.
- [x] 백엔드와 프론트 검증 명령이 통과한다.
